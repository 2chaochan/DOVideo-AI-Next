# 08 怎样判断 Agent 做得好并控制消耗

“接口返回成功”只说明流程完成到某个状态，不能单独说明答案正确。视频 Agent 还需要检查是否回答用户目标、是否有合适证据，以及花费的时间和资源是否合理。

## 质量和工程指标一起看

| 维度 | 可以问的问题 |
| --- | --- |
| 目标完成 | 用户要求的重点有没有覆盖？ |
| 证据质量 | 结论能否回到视频片段核对？ |
| 结构完整 | 页面所需字段是否齐全？ |
| 延迟 | 从受理到结果要多久，慢在哪个阶段？ |
| 消耗 | 调用了几次模型，估算用了多少 Token 和费用？ |

Critic 是一次任务内部的检查环节；离线评估则让一组固定任务反复运行，比较不同版本的表现。二者相互补充，不能把 Critic 通过直接当成客观正确率。

## 预算怎样限制任务

`AgentExecutionBudget` 和 Agent 循环中的配置约束轮次、时长与消耗。请求限流控制一段时间允许接收多少次请求；单任务预算控制一次任务最多花多少。这是两个不同层次。

`AgentTelemetry` 记录阶段耗时、调用次数及估算消耗。费用估算依赖 Token 估计和配置单价，不能直接当成供应商的最终账单。价格未配置或费用限制关闭时，也不能声称系统已经按实际金额止损。

## 怎样学习一次模型变更

先读 [AgentEvaluationService](../../../server/src/main/java/com/example/server/service/AgentEvaluationService.java)、`OfflineAgentEvaluationRunner` 和 `resources/evaluation/golden-video-tasks.json`。理解每项任务的目标、预期和评分方式，再研究是否需要扩充。

后续实验可以固定一组视频和问题，只改变一个提示词或模型配置，同时记录质量、耗时和估算费用。记录模型及提示词版本，避免把不同条件下的结果直接比较。

自测：新版本回答更长，是否就更好？请从目标覆盖、证据、延迟和费用四个方面回答。
