# 05 后端怎样把视频整理成模型能用的资料

本项目的后端会先提取视频中的语音和画面信息，再将文字、时间区间和图片证据整理成统一上下文，供后续分析使用。

## 两条提取分支

ASR 是语音识别，回答“这段时间说了什么”。OCR 是图片文字识别，回答“画面上写了什么”。FFmpeg 负责音视频处理，例如音频切分和抽取关键帧；它本身不负责理解用户问题。

例如，一段课上老师说“这里要先访问根节点”，黑板同时写着“前序遍历”。把两种信息结合，后端才能为模型提供更完整的资料。

## 为什么要保留时间

只有文字结论，用户很难核对依据。保存时间区间后，结果可以指向原视频片段，后端也能检查引用时间是否落在有效证据范围内。

下面是帮助理解的示例，不是接口返回的精确 JSON 格式：

```text
时间：02:00 到 03:00
语音：先访问根节点，再访问左右子树
画面文字：前序遍历
证据：这一时间范围的关键帧
```

实际结构见 [VideoContext](../../../server/src/main/java/com/example/server/dto/VideoContext.java)。它包含 `source`、`userGoal` 和片段列表；片段里保存毫秒起止时间、语音文本、OCR 文本及证据帧。

## 为什么统一结构有用

后续检索和 Agent 可以读取统一片段，不必分别理解每个 ASR 或 OCR 服务的输出格式。基础识别能力变化时，尽量在转换层处理差异，减少对整个分析链路的影响。

长视频内容也不能无限塞进一次模型请求。后端还会进行分块、摘要和检索，选出与当前目标相关的证据；下一章之后会继续解释。
