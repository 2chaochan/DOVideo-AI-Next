# 00 先认识后端和大模型

本教程用同一个业务例子贯穿各章：用户上传一段二叉树课程视频，输入“整理前序遍历步骤，并给出视频证据”。最终希望看到学习笔记、可定位的时间戳，还能继续问“为什么先访问根节点”。

在看 Java 类之前，我们先把这件事需要的基本概念讲清楚。本章不要求会 Spring 或部署数据库；先能解释数据从哪里来、程序怎样处理、结果放在哪里。

## 1 程序 服务和前后端

程序是按照规则处理输入并产生输出的指令。一个持续运行、等待别的程序请求的程序，可以提供“服务”。本项目后端就是一个运行中的 Java 服务。

前端是浏览器里的页面，负责接收点击、文件和文字，展示进度与结果。后端负责校验身份、保存文件、安排分析、调用模型和保存结果。浏览器刷新后页面内存会重建，所以长期数据需要交给后端存储。

在案例里，“点击分析”是前端交互，“判断视频是否属于你”是后端规则，“生成学习笔记”则需要后端组织模型和证据共同完成。

## 2 HTTP 请求是两个程序交流的一种方式

浏览器和后端不共享一个普通 Java 方法栈，需要通过网络交换消息。HTTP 规定请求和响应怎样表达。一个请求通常包括方法、路径、请求头以及可选的请求体。

```http
GET /health HTTP/1.1
Host: localhost:9090
```

`GET` 表示读取，`/health` 是要访问的路径，`localhost:9090` 表示当前电脑上的 9090 端口。端口可以理解为同一台机器上不同服务的入口编号。服务没有启动，地址写对也无法得到正常响应。

本项目健康接口的业务响应可以写成：

```json
{"code":0,"message":"success","data":"UP"}
```

JSON 是一种文本数据格式：花括号表示对象，键对应值，方括号表示列表。它让不同语言的程序能交换有结构的数据。HTTP 状态码和 JSON 中的 `code` 是两层信息：前者表达请求处理语义，后者是本项目的业务约定。

HTTP 本身不会自动把两次请求认作同一个登录用户，应用需要会话等机制建立关联。[HTTP 基础可查阅 MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview)。

## 3 内存 数据库 缓存和文件存储

假设服务先把“视频 42 分析完成”存在一个 Java 变量里。进程退出后，这个变量就没有了。为了在重启后找回结果，需要持久化，也就是把数据保存到程序内存之外的存储中。

关系数据库把数据组织成表。`media_files` 的一行对应一条媒体记录，`id` 是区分记录的主键，`user_id` 表示归属。SQL 是读写这些表的语言，例如下面是学习用查询，不是让你修改数据库：

```sql
SELECT id, filename FROM media_files WHERE user_id = 7;
```

视频文件体积很大，项目把文件内容放在 MinIO 对象存储，把文件地址等元信息放在数据库。Redis 则承担会话、临时状态、缓存、锁和限流等用途。缓存通常用来加快读取，但不是所有 Redis 键都只是可随意丢失的缓存：未完成上传的状态丢失就会影响续传。

学到这里，应该能解释：数据库中的一条媒体记录和磁盘上的一段视频不是同一个东西，两者需要关联。

## 4 大模型 Prompt Token 和上下文

大语言模型能根据输入生成文字。后端通常通过服务接口发送材料并接收结果。一次模型调用仍然是网络操作，可能超时、失败，输出也可能与预期格式不同。

Prompt 是给模型的指令和材料。例如“只根据下面课程片段说明前序遍历顺序，并引用时间戳”。上下文是这次调用实际提供给模型的信息，包括任务要求、视频片段、计划或历史对话。程序知道某条信息，不代表模型本次调用也能看到；需要把有关信息组织进输入。

Token 是模型处理文本的计量单位，不固定等于一个汉字或一个单词。上下文长度和输入输出消耗受到限制，所以长视频不能无限追加到一次请求里。

模型可能生成看起来合理却没有材料支持的内容。这类风险不能靠“请务必准确”一句提示消除。项目需要检索证据、限制输出结构、检查结果，并允许表达不确定性。

## 5 普通模型调用和 Agent 编排

最简单的应用是“输入文字 → 调用模型 → 展示回答”。当任务需要先找资料、制定计划、执行后检查、必要时补充材料时，后端还要组织这些步骤，并保存状态。

本项目把这种有目标、有步骤、有反馈的执行过程组织为 Agent 闭环。它的流程边界由代码规定：Planner 负责计划，Executor 负责生成，Critic 负责检查，后端决定是否再执行以及何时停止。

这是受控的 Agent 实现。其他项目可能让模型动态选择工具，本项目不能因此被描述成一个任意自主执行命令的系统。学习时应先说明当前实现究竟允许什么。

## 6 看 Java 源码前认识几个词

类可以先理解为一种对象的定义，对象是程序运行时使用的具体实例。方法是一段有名字、可以传入参数并返回结果的处理逻辑。`complete(uploadId, userId)` 表示把两个值传给完成方法。

`Long`、`String` 等类型约束变量保存什么数据。DTO 是用于传递数据的对象；Entity 通常对应需要保存的业务数据。它们是职责名称，不会仅凭名字自动读写数据库。

构造器用于创建对象并提供依赖。比如上传服务需要 Redis、MinIO 和仓储对象，项目让 Spring 创建并注入它们，这叫依赖注入。初学时先把它理解为“由框架把需要的协作者交给这个类”，再逐步学习容器与代理。

异常表示某一步不能按正常路径继续。`throw` 向调用方报告问题，`try/catch` 处理可能的失败，`finally` 适合释放锁或临时资源。异常被捕获并不表示业务已恢复，要看处理分支实际做了什么。

Mapper 通常承担数据库读写映射；Repository 可以组织持久化行为。它们与 Service 的职责边界由本项目结构和规则决定，不必先背一套复杂架构理论。

## 7 第一项无需模型密钥的练习

阅读 [HealthController](../../../server/src/main/java/com/example/server/controller/HealthController.java) 和 [Result](../../../server/src/main/java/com/example/server/common/Result.java)，找到 `/health` 与 `UP`。暂时不用启动全部服务，只把请求路径、方法返回值和 JSON 结构对应起来。

问题：浏览器刷新后，为什么视频列表还能存在？参考答案：列表数据由后端从存储中获取，长期记录不依赖这次页面进程的内存。

问题：模型为什么不知道你电脑上视频的内容？参考答案：文件存在本机不等于已经进入模型输入，需要后端提供服务支持的材料；本项目主要先提取语音和画面文字再组织证据。
