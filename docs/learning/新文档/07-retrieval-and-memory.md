# 07 从查资料理解检索和记忆

如果课程只有一分钟，把有关文字交给模型较容易。如果视频长两小时，还讨论了很多其他主题，输入过长会增加延迟、消耗上下文空间，也可能淹没重点。

用户问“前序遍历的常见错误”时，我们希望先找到有关片段，再生成答案。这就是检索为生成准备资料的基本思路。

## 1 分块 摘要和关键词各做什么

分块把长资料拆成较小单元。摘要概括每块内容，关键词提供容易匹配的线索。它们像书的章节和目录，帮助定位，但目录不能替代正文作为全部证据。

本项目的 `VideoChunkingService` 和 `LongVideoContextService` 组织长视频资料，再由检索能力挑选相关片段。前面音频处理的片段与检索使用的较大知识分块不是同一层，阅读代码时要区分。

## 2 关键词与向量检索

关键词检索利用文字命中。例如提问包含“前序”，片段也有“前序”，容易找到。但用户说“先访问哪个节点”，原文只说“根左右”，字面命中就可能不足。

Embedding 把文字转换成一组数值，向量相似度用来衡量表达是否接近。语义相关的表达更有机会被一起找到，但相似并不意味着事实一致。否定句、专业术语或识别错误都可能影响结果。

Qdrant 负责存放和查询向量索引，不是替代文字模型生成答案。`VideoEvidenceRetrievalService` 结合语义、关键词等信息排序。这里不应把“用了向量数据库”直接写成“已经保证检索准确”。

## 3 RAG 在这个项目里如何理解

RAG 可以按“检索增强生成”理解：先检索相关资料，再把资料交给模型生成结果。它不要求重新训练模型参数。

教学过程是：用户目标 → 找到 02:00 到 03:00 的遍历片段 → 把片段及时间交给执行阶段 → 生成带证据的学习笔记。检索提高材料相关性，但结果仍可能因召回遗漏、原材料错误或模型生成偏差而出错。

检索失败时项目存在降级路径。降级表示尽量保住可用性，不表示质量完全不变。诊断问题时要知道这一轮究竟用了哪种检索路径。

## 4 三种常被叫作记忆的东西

对话历史帮助理解用户继续问的“那它呢”；视频知识与索引帮助找课程材料；检查点记录程序已经做完的阶段和产物。三者回答的问题不同。

例如用户问“那中序遍历有什么区别”，需要把“那”与前面的讨论联系；服务重启后知道音视频已提取完成，则需要持久化阶段记录。把历史对话放进 Prompt 不会自动恢复程序执行位置。

本项目追问上下文使用 Redis 保存；检查点以 MySQL 持久化配合 Redis 热缓存。丢失不同状态，会造成不同恢复能力变化。

## 5 检查点为什么需要任务身份

假设视频相同，但第一次问学习笔记，第二次问审查论证漏洞。直接把第一次最终结果返回第二次会混淆目标。所以计划、结果和阶段都需要按适当的媒体、目标、模式身份读取。

恢复也不是见到某个 JSON 就全部相信。`AgentLoopService` 会检查保存的计划和结果是否有效，再决定复用、修复或继续执行。状态来自以前，不代表一定适合当前流程。

## 6 实践和答案

阅读 [AgentCheckpointRepository](../../../server/src/main/java/com/example/server/repository/AgentCheckpointRepository.java) 和 `AgentCheckpointService`，找到持久化与缓存读写；再从检索服务找 `search` 和排序代码。

问：把所有聊天历史永久追加，是否就有了更好的记忆？答：不一定，会增加输入、引入过期或无关信息，还要考虑隐私和上下文限制，应按任务选择材料。

问：模型忘了上一句和程序重复识别音频，是同一个故障吗？答：不是，前者涉及对话输入，后者可能涉及阶段恢复和持久化产物复用。
