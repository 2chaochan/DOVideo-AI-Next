# 07 长视频怎样找证据并接着上次继续

一段两小时的视频可能包含很多主题。用户只问“二叉树遍历为什么容易出错”，后端应尽量找相关片段，而不是把整段转写反复交给模型。

## 检索是在资料里挑重点

关键词检索看文字是否匹配，向量检索用数值表示文本含义，帮助找到表达不同但语义相关的片段。本项目结合片段摘要、关键词与向量能力，再取相关原始证据供分析。

可以把摘要看成目录，把原始片段看成正文。目录方便定位，最终结论仍需要能核对的正文依据。检索遗漏了关键片段，后续模型即使表达流畅也可能回答不完整。

`QdrantVectorStore` 辅助语义检索。项目有降级路径，向量服务不可用时尽量使用现有关键词或向量排序能力；降级提高可用性，不保证效果完全不变。

## 三种状态不要混在一起

| 状态 | 用途 |
| --- | --- |
| 视频知识与索引 | 按问题寻找有关片段 |
| 追问上下文 | 让后续问题能结合对话历史理解 |
| Checkpoint 检查点 | 记录处理阶段与产物，帮助任务恢复 |

例如“那这个地方有什么例外”需要对话上下文来解释“这个地方”；进程中断后知道音视频已经提取完成，则依赖阶段产物与检查点。它们不是同一种记忆。

## 恢复为什么依赖持久化

当前检查点采用 MySQL 持久化并配合 Redis 热缓存。缓存适合快速读取，持久化记录用来保留恢复依据。恢复前还需要检查任务身份和已保存阶段，不能把另一个目标或模式的结果直接当作当前任务完成。

阅读 [AgentCheckpointRepository](../../../server/src/main/java/com/example/server/repository/AgentCheckpointRepository.java)、`AgentCheckpointService`、`LongVideoContextService` 和 `VideoEvidenceRetrievalService`，分别找出写入位置、读取位置及降级分支。
